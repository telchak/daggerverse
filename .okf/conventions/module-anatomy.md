# Required (CI errors)

| File | Rule |
|------|------|
| `dagger-module.toml` | must exist; CI discovers modules by it[^ci] |
| `src/<pkg>/__init__.py` | its docstring's first line, the description, must not be empty[^ci] |
| `README.md` | must exist |
| `examples/` | must exist; in practice `examples/{go,python,typescript}/` each a small Dagger module calling this one |
| module loads | `dagger api functions -m ./<module>` must succeed |
| generated code | the `check` job's `dagger check` fails when the committed `sdk/`, `clients/` or entrypoint types differ from `dagger generate` |

# Contents

- `dagger-module.toml`, the module manifest, in one of two shapes. It has no `description` and no
  dependency list.
  - Plain modules and `tests`: `name` plus `[entrypoint] kind = "dang"`,
    `source = "./sdk/entrypoint"`.[^manifest] This **static entrypoint** is generated Dang code with
    the module's types baked in; there is no `engineVersion`, the module runs on the engine's own
    version, and a function signature change needs `dagger generate -y`.
  - Agents: `name`, `engineVersion = "v1.0.0-0"` (written by the SDK), `include = ["../_agent_base"]`
    and `[runtime] source = "dagger.io/sdk/python/runtime@v1"`.[^agent-manifest] This **runtime
    manifest** builds the module at load time, which the agents need for `dag.current_node()`
    (`legacyRuntime = true` in their scope settings).
- The module's scope in the root `dagger.toml`: `[sdks.python.scopes.<module>]` with
  `is-module = true` and `clients = [...]`, its dependencies (relative paths in-repo, pinned Git
  refs for external modules).[^workspace] See [Dagger 1.0 workspaces](/dagger/dagger-1-0-workspaces.md).
- `src/<pkg>/__init__.py`: the docstring **is** the description shown on daggerverse.dev; start
  its text on the line after the opening `"""` and replace any template boilerplate.[^publishing]
  See [Daggerverse publishing](/dagger/daggerverse-publishing.md).
- `pyproject.toml`: a uv workspace whose members are `sdk` and `clients/*`, with
  `[tool.dagger] global-client = true`; plus a committed `uv.lock`, since modules build with
  `uv sync --locked` (see [SonarCloud](/infrastructure/sonarcloud.md)). The `uv_build` version
  comes from the Dagger template; do not bump it.
- Generated by `dagger generate` and **committed**: `sdk/` (the vendored `dagger-io` library, plus
  `sdk/entrypoint/*.dang` for plain modules), `clients/core` and one `clients/<dependency>` per
  client.[^contributing] Never edit them by hand: change the source or the scope and
  regenerate.[^claude]
- Every module but `goose` and `speck` carries a `.gitignore` (`/.venv`, `/**/__pycache__`,
  `/.env`; `/sdk` is no longer ignored) and a `.gitattributes` marking `/sdk/**` as
  `linguist-generated`.
- `examples/` modules stay on `dagger.json`: 1.0 still loads them against the migrated modules,
  so they need no generated code.
- Agents only: `src/<pkg>/prompts/`, optional `.agent-tests` (test suffixes) and `.agent-gcp`
  (needs GCP credentials).

# Gotcha

After changing a function signature, a scope's `clients` or the Dagger version, run
`dagger generate -y` and commit `sdk/`, `clients/` and `uv.lock`, or CI's `check` job fails.[^claude]
(The 0.x gotcha of `dagger develop` stripping `description` from `dagger.json` went away with
`dagger.json`.)

# Size

Keep sources under 600 lines; CI only warns above it (`tests/src/tests/main.py` is over).[^ci]
