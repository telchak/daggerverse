# Required (CI errors)

| File | Rule |
|------|------|
| `dagger.json` | must exist and contain `"description"`[^ci] |
| `README.md` | must exist |
| `examples/` | must exist; in practice `examples/{go,python,typescript}/` each a small Dagger module calling this one |
| module loads | `dagger functions` must succeed |

# Contents

- `dagger.json`: `name`, `description`, `engineVersion` (kept in sync by
  [Renovate](/infrastructure/renovate.md)), `sdk.source: python`, `dependencies` (relative
  paths in-repo, pinned git URLs for external), and `include: ["../_agent_base"]` for agents.
- `src/<pkg>/__init__.py`: the docstring **is** the description shown on daggerverse.dev, not
  `dagger.json`'s `description`. Replace any `dagger init` boilerplate.[^publishing] See
  [Daggerverse publishing](/dagger/daggerverse-publishing.md).
- `pyproject.toml` + committed `uv.lock` (see [SonarCloud](/infrastructure/sonarcloud.md)).
  `uv_build` version comes from the Dagger template; do not bump it.
- `sdk/` is generated by `dagger develop`, git-ignored, marked `linguist-generated`.
- `.gitignore` per module: `/.venv`, `/**/__pycache__`, `/sdk`, `/.env`.
- Agents only: `src/<pkg>/prompts/`, optional `.agent-tests` (test suffixes) and `.agent-gcp`
  (needs GCP credentials).

# Gotcha

`dagger develop` strips the `description` field from `dagger.json`; re-add it afterwards or
`validate` fails.[^readme]

# Size

Keep sources under 600 lines (CI warning). CONTRIBUTING still says 300, see
[documentation drift](/conventions/documentation-drift.md).[^contributing]
